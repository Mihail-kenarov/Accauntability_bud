# Product

## Register

product

## Users

The primary user is Mihail: a busy student preparing to become an entrepreneur in the upcoming months. The app is used in ordinary daily moments: morning planning, mid-day replanning, and evening reflection. The user needs a private accountability partner that understands calendar commitments, personal goals, habits, missed plans, and recurring constraints.

## Product Purpose

Accountability Bud is a conversational life coach web app that helps the user plan realistic days, stay honest about personal goals, and build consistency over time. It combines Google Calendar context, remembered personal facts, saved daily plans, and habit streak data so the assistant can respond with grounded coaching instead of generic chatbot advice.

Success means the user can open the app, understand the day, talk through decisions, adjust plans when life changes, and review whether habits are improving. The app should feel useful enough to become a daily check-in surface, not a novelty demo.

## Brand Personality

Focused, reflective, and quietly direct. The voice should feel like a private coach who knows the user well: warm enough to be trusted, honest enough to create accountability, and restrained enough to stay out of the way. It should borrow the calm productivity feel of Notion while adding a more personal, reflective coaching layer.

## Anti-references

This should not look or feel like a generic chatbot, a corporate analytics dashboard, a childish habit tracker, a dark hacker terminal, an over-gamified streak app, or an elegant luxury brand site. Avoid loud motivational graphics, excessive badges, confetti, heavy gradients, and dashboard clutter that makes the user manage the tool instead of their day.

## Design Principles

1. Keep the conversation central, but surround it with evidence. Calendar, plan, memory, and habit state should support the chat without taking over the screen.
2. Make accountability feel private and specific. The UI should help the agent reference real commitments and patterns, not vague productivity advice.
3. Prefer calm focus over gamification. Streaks and habits matter, but they should be presented as honest signals, not as a game layer.
4. Show grounding without exposing machinery. Tool usage should appear as human-readable context and source traces, not raw developer logs.
5. Design for daily use on laptop and phone. The app should be clear, light, and comfortable for repeated check-ins.

## Accessibility & Inclusion

Target WCAG AA contrast for text and interactive controls. Use a light theme with readable type, clear focus states, and large enough tap targets for mobile. Smooth animations should be subtle and state-driven, with reduced-motion behavior respected for users who prefer less motion.
